# 時間割作成くん リファクタ＆改善 引継ぎドキュメント

## プロジェクト概要

学習塾向けの講習時間割作成ツール。「日付・時限・クラス」のマトリクスに対し、講師を割り当てる。
現在は「冬期講習」用だが、夏期・春期など汎用的に使えるよう改修する。

- **利用者:** 1名（ローカル環境、GitHub Pages等でホスティング）
- **同時編集:** 不要（共有はJSON出力ファイルの受け渡しで対応）
- **次回利用:** 2025年夏頃（時間的余裕あり）
- **現バージョン:** v45（App.jsx 単一ファイル、約870行）
- **技術スタック:** React, Vite, Tailwind CSS, SheetJS (XLSX)

### スケジュールキーの問題

現在のキー形式: `"12/25(木)-1限 (13:00~)-３S"`

日本語文字列を `-` で結合しているため、値自体に `-` が含まれるとパースが壊れるリスクがある。インデックスベースのキーに移行すべき。

## 現在の機能一覧

### 基本操作
- セル（科目・講師）のドロップダウン選択
- ドラッグ＆ドロップによるセル入れ替え
- 右クリックメニュー（コピー、貼り付け、ロック切替、NG登録、クリア）
- 日付/時限/クラスヘッダーの右クリック → 名称変更、一括ロック/解除/クリア
- キーボード矢印キーでセル間移動
- コンパクト表示切替

### データ管理
- マルチタブ（中3、中1・2など独立構成）
- タブの追加、削除、名前変更（ダブルクリック）
- プロジェクト保存/読込（JSON）
- localStorage 自動保存
- 設定のデフォルト保存
- Undo/Redo（project全体のスナップショット方式、最大50件）

### 設定モーダル（4タブ構成）
- **基本設定:** 日付・時限・クラス（カンマ区切りテキスト入力）、科目ごとの必要コマ数、講師マスタ（氏名・担当科目）
- **クラス優先度:** 講師×クラスの優先/NG/普通の3段階切替
- **他学年・午前:** 講師×日付の外部コマ数入力
- **日時NG:** 講師×（日付×時限）のNG切替

### 分析・表示
- 進捗バー（埋まったセル / 総コマ数）
- 重複検知（タブ横断で講師の物理的重複をチェック、赤ハイライト＋アニメーション）
- 科目回数の丸数字表示（①②③…）、超過時に赤字＋!
- 同日同クラス同科目の重複警告
- 講師別コマ数集計パネル

### 自動生成（MRV法 + バックトラッキング）
- 候補者が少ないコマから優先的に埋める
- クラス優先度（優先 > 通常 > NG）を考慮
- 50万イテレーション制限
- ロック済みセルは保持

### 出力
- Excel出力（全体シート）
- Excel出力（講師別シート）
- 印刷用CSS（@media print、横向き）

### Step 2：UI/UX改善

#### 2-1. テーブルの見やすさ・操作性

- **科目カラーの固定マップ化:** 現在のハッシュベースランダム割当を廃止し、科目ごとに固定色を設定（設定画面で変更可能に）
  ```js
  // 例
  const DEFAULT_SUBJECT_COLORS = {
    "英語": "#DBEAFE",  // 青系
    "数学": "#FEE2E2",  // 赤系
    "国語": "#FEF3C7",  // 黄系
    "理科": "#D1FAE5",  // 緑系
    "社会": "#EDE9FE",  // 紫系
  };
  ```
- **スティッキー列のCSS整理:** 手動の `left` 値計算（`3rem`/`5rem`）を CSS変数 or 動的計算に
- **セルの情報密度の改善:** コンパクトモード時のレイアウト最適化

#### 2-2. alert/prompt/confirm の全廃

現在 `alert` / `prompt` / `confirm` を多用しており、操作の流れが中断される。全てカスタムUIに置き換える。

| 現在の使用箇所 | 置き換え先 |
|---|---|
| `prompt("新しいタブの名前:")` | インラインの入力フィールド or 小さなモーダル |
| `prompt("講師名:")` | 講師追加フォーム（設定モーダル内） |
| `confirm("このタブを削除しますか？")` | 確認モーダル（取り消しボタン付き） |
| `confirm("ロックされていないセルを全てクリアしますか？")` | 確認モーダル |
| `alert("読込完了")` | トースト通知（数秒で自動消滅） |
| `alert("完全なパターンが見つかりませんでした…")` | 結果パネル内にメッセージ表示 |
| ヘッダー右クリック→ `prompt("新しい名称を入力:")` | インライン編集（ダブルクリックで編集モード） |

#### 2-3. 設定画面の操作性

- **講師名の編集機能:** 講師マスタで氏名をクリック → インライン編集。変更時に全タブのスケジュールデータも自動追従。
- **科目マスタの独立管理:** 現在は `subjectCounts` のキーで暗黙的に管理されている科目一覧を、明示的な科目マスタとして切り出す。科目の追加・削除・並び替えが自由にできるように。
- **NGテーブルの改善:** 日付×時限が多いとテーブルが巨大になるため、日付ごとの折りたたみ or フィルタ機能を追加。

#### 2-4. 操作ガイダンス

- 初回表示時の簡易オンボーディング（「右クリックで名称変更」「ドラッグで入れ替え」等のチップス）
- ツールチップの追加（ボタンやアイコンのホバー時）

### Step 3：自動生成の強化

#### 3-1. 複数案の生成

現在のコードは `solutions.length >= 1` で打ち切っているため、実質1案しか生成しない。UIの「3案」表示に合わせて、実際に3案生成するようにする。

**方針:** シード（ランダム順序）を変えて複数回ソルバーを実行。各回で異なる初期シャッフルを使うことで、異なる解を得る。

```js
// 擬似コード
const NUM_PATTERNS = 3;
for (let i = 0; i < NUM_PATTERNS; i++) {
  const solution = solveWithSeed(i);
  if (solution) solutions.push(solution);
}
```

#### 3-2. 部分解の提示

現在、完全解が見つからない場合は `alert` を出すだけで部分解を返していない。失敗時にも「ここまで埋められた」という案を提示する。

#### 3-3. Web Worker化（将来的に）

現在は `setTimeout(fn, 100)` でメインスレッドをブロックしている。Web Worker に移すことでUI のフリーズを防ぐ。プログレスコールバックで進捗表示も可能に。

## 既存コードの注意点

### localStorage の使用

```js
const STORAGE_KEY_PROJECT = 'winter_schedule_project_v45';
const STORAGE_KEY_USER_DEFAULTS = 'winter_schedule_user_defaults';
```

ローカル環境での使用なので localStorage は問題ないが、キー名の `winter_` プレフィックスは汎用化に伴い変更する。

### Undo/Redo の実装

`project` 全体をスナップショットとして配列に積む方式（最大50件）。タブやデータが増えるとメモリ消費が大きくなる。将来的には差分ベースの履歴管理（immer 等）への移行を検討。ただし当面はこのままでも実用上問題なし。

### 自動生成ロジックの詳細

- MRV（Minimum Remaining Values）法: 候補者が少ないコマから埋める
- バックトラッキング: 行き詰まったら戻って別の候補を試す
- 50万イテレーション上限
- 優先順位: 優先クラス講師 > 通常講師（NG講師はフィルタで除外済み）
- タブ横断での重複チェックは `globalUsage` で管理
- ロック済みセルはスキップ、科目が設定済み（講師のみ未定）のセルは科目を保持して講師のみ割当

### scrollToFirstError の軽微なバグ

```js
// L204-206: some() の戻り値の扱いが不正（if文の位置がずれている）
// 動作はしているが、構造的に修正すべき
```

## 技術的な制約・方針

- **フレームワーク:** React + Vite + Tailwind CSS を維持
- **状態管理:** React Context + useReducer（Redux等は不要）
- **UI ライブラリ:** 導入しない方針（Tailwind で十分、依存を増やさない）
- **テスト:** 自動生成ロジックにはユニットテストを追加したい（Vitest）
- **ビルド:** Vite のまま、GitHub Pages へのデプロイを想定
